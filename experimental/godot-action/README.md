# 【アーカイブ】相剋のビルドサーガ ACTION（Godot 4）

> **この実装は現在使われていません。**
> 本体はリポジトリ直下の**Web版（ターン制RPG）**です。
>
> 2Dアクションとして作り直す試みでしたが、アクションの手応えを出すには
> キャラクターのアニメーション素材が要る一方、ターン制なら1枚絵で成立するため、
> ターン制に戻すという判断になりました。素材の制約はアクション特有の問題です。
>
> ここに残してあるのは、方針が変わったときに参照できるようにするためです。
> `experimental/godot-action/project.godot` を Godot 4.3以降で開けば、そのまま動きます。
>
> **ここで書いた資産のうち、以下はターン制のGodot版を作る場合そのまま使えます**
> （データ層 `data/*.json`、ドット絵 `assets/sprites/`、`scripts/` の
> game_data / hero_state / combat / equip_screen / tree_screen / self_test / skill_runner）。

---

Web版（リポジトリ直下）のビルドシステムを、**2Dアクション**として作り直すための土台です。
現状は**アリーナ1面の縦切り（バーティカルスライス）**で、ビルドの数値が操作と手応えに
反映されることを確認するためのものです。

## 動かし方

1. **Godot 4.3 以降**を用意する（GDScript版でよく、.NET版は不要）
2. Godot を起動し、「インポート」から `godot/project.godot` を選ぶ
3. **初回は必ずエディタで開くこと**（241枚のPNGのインポートが走ります）
4. F5 で実行

| 操作 | キー |
| --- | --- |
| 移動 | WASD / 矢印 |
| 斬撃 | Space または 左クリック |
| スキル | 1〜4（職業のスキルが自動で割り当てられる） |
| 装備画面 | I（開いている間はポーズ、Esc でも閉じる） |
| スキルツリー | T（共通ツリー／職業ツリーを切り替え） |
| 回避ダッシュ | Shift（回避率が高いほど無敵時間が伸びる） |
| ビルド表示 | Tab |
| リトライ | Enter（ゲームオーバー時） |

## いま動くこと

- 職業選択（初級4職）→ アリーナで戦闘 → 敵を全滅させると次の階層
- **スキルが撃てる。** 職業のスキルが1〜4に割り当てられ、MPとクールダウンで撃つ。
  転職やツリーで増えたスキルもそのまま候補に入る（`hero_state.skill_list()`）
  - 単体／全体／ランダム を、アクションでは「最寄りの敵／画面内全部／ランダム1体」と読み替える
  - 特殊計算も移植済み: 物魔平均（魔剣士）、素早さ加算（神速天翔）、
    反射比例（守護者）、アイテム威力比例（錬金術士）、ミシック数比例（虚無帝）、全属性連撃
- **状態異常**（火傷・毒・凍結・麻痺）。凍結で鈍化、麻痺で停止、火傷と毒は継続ダメージ
- **敵が攻撃してくる。** 予備動作（赤く光って動きが鈍る）→ 飛び道具。避ける意味がある
- **見た目の作り込み**（1枚絵しか無いぶん、手続きで動きを作っている）
  - **影**: 全キャラの足元に楕円の影。浮いて見えないための土台
  - **手続きアニメーション**: 走ると前傾し、上下に揺れ、縦横に伸縮する。
    被弾・踏み込み・ダッシュでは一瞬つぶれる（`visual.gd`）
  - **斬撃**: 止まった扇ではなく、刃が走った跡として三日月が掃く
  - **パーティクル**: 命中の火花、会心の飛沫、走行時の土煙、
    撃破時は**スプライトの色を拾ってバラバラに飛び散る**（`fx_layer.gd`）
  - **カメラ**: 世界（1680×960）を窓より大きく取り、追従カメラで見る。
    画面＝箱に見えないように
  - **床**: タイルの濃淡・汚れ・外周の暗がりで「場所」に見せる
  - 敵の予備動作中は足元に赤い輪。敵弾には軌跡
- **手応えの作り込み**（控えめに）
  - ヒットストップ: 当てた瞬間に世界が止まる。会心は少し長く
  - ノックバック: 会心ほど強く押す
  - 画面の揺れ: 会心と被弾のときだけ、ごく小さく
  - 被弾フラッシュ、状態異常ごとの色づけ、ダメージ数字
- ビルドの数値が実際に効いている
  - **会心率／会心ダメージ** → ダメージ計算に反映（金色の数字）
  - **波及率** → 斬撃の扇が広く長くなり、範囲外の敵にも減衰して届く
  - **反射率** → 接触してきた敵に返す
  - **吸収** → 与ダメージに応じて回復
  - **素早さ** → 移動速度・攻撃間隔・回避の無敵時間
  - **属性／耐性貫通** → 武器とスキルの属性が敵の弱点／耐性と噛み合う
  - **特殊効果フラグ** → 会心時の防御無視、瀕死特効、被ダメ軽減、撃破時回復、
    回復超過分のバリア化、攻撃時の状態異常付与 など
- バリア、一時強化（バフ）、一時フラグ、敵への弱体
- **装備画面（I キー）**。武器・防具・アクセサリ4枠を組み替えられる
  - 階層を踏破するたびアクセサリが手に入る（レジェンドは階層が深いほど出やすい）
  - 同じ個体を2つの枠に付けることはできない（Web版と同じ制約）
  - 組み替えると即座にステータス・スキル欄・操作感（移動速度や攻撃間隔）に反映される
  - 武器を替えると通常攻撃の属性が変わり、武器が持つスキルも使えるようになる
- **スキルツリー画面（T キー）**
  - **共通ツリー**（9系統54ノード）: SPを振って伸ばす。前提ノード・系統への投資量・
    職業限定の奥義ノードといった条件を、満たしていない理由まで表示する。
    ゴールドで振り直せる
  - **職業ツリー**（3段2択）: 階層を踏破すると習熟度が貯まり、段が開く。
    各段は片方しか選べないので、同じ職業でも分岐する
  - どちらもステータス・特殊効果・スキル欄に即座に反映される
- レベルアップとSP獲得、階層踏破ごとの習熟度獲得
- **起動時の自己診断**（デバッグ実行時）。25職すべてのビルド集計、138アクセの装備、
  27種の武具、ダメージ計算、敵のスケーリング、職業ツリーの整合を確認し、
  問題があれば画面と出力ログに出す

## まだ無いもの（次にやること）

- 階層ノードの選択と報酬3択、行商人、焚き火、転職の祭壇
- 転職（職業を変える手段がまだ無い。上級職・最上級職に到達できない）
- ミシックの取得条件判定（`cond.code` は書き出し済み。24種の判定を実装するだけ）
- アイテム（`makeItem` を持つスキルは、その部分だけ現在は無視される）
- ボス、階層ごとのノード選択、報酬の3択
- **効果音**（現在は完全に無音。ここが残りの体感差の大きな部分）
- **描き起こしのアニメーション**（歩き・攻撃のコマ）。手続きの作り込みで届く範囲には
  限界があり、ここから先は絵の作業になる

## データとアセットの出どころ

**Godot側のデータは手で編集しないでください。** Web版から自動生成しています。

```bash
node tools/export-data.js        # js/data/*.js  -> godot/data/*.json
node tools/export-sprites.js     # 手続き生成のドット絵 -> godot/assets/sprites/*.png (241枚)
node tools/validate-godot-data.js # Godot側が読むキーが揃っているかの検証
```

バランス調整や新しいアクセサリの追加は Web版（`js/data/`）で行い、
上のコマンドで書き出すと Godot 側にも反映されます。データの二重管理を避けるためです。

## 構成

```
project.godot            プロジェクト設定（描画はNearest固定＝ドット絵が滲まない）
data/*.json              Web版から生成したデータ（職業25/アクセ138/スキル86/ツリー204ノード）
assets/sprites/**        16x16のPNG 241枚（Web版と同じ絵）
scripts/
  game_data.gd           JSONの読み込みと引き当て（Autoload）
  hero_state.gd          ビルド集計（js/core/stats.js の移植）
  combat.gd              ダメージ計算（js/core/battle.js の strike() の移植）
  player.gd / enemy.gd   アクション側の実体。物理エンジンは使わず距離判定
  main.gd                アリーナ・ウェーブ・判定の取りまとめ
  hud.gd / damage_popup.gd / ui_theme.gd
```

日本語表示には `SystemFont` を使い、OSのフォントを借りています
（フォントを同梱しないので、ライセンス上の制約を持ち込みません）。
